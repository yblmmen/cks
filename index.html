1. API Server 감사 로그(Audit Log) 활성화

클러스터 내에서 발생하는 주요 API 요청/응답 이력을 기록하고 추적하기 위한 감사 정책과 옵션을 설정합니다.

① 감사 정책 파일 작성 (/etc/kubernetes/audit/audit-policy.yaml):

apiVersion: audit.k8s.io/v1
kind: Policy
rules:
- level: RequestResponse
  resources:
  - group: ""
    resources: ["pods", "secrets", "configmaps"]

② API Server 매니페스트 수정 (/etc/kubernetes/manifests/kube-apiserver.yaml):

spec:
  containers:
  - name: kube-apiserver
    command:
    - kube-apiserver
    - --audit-policy-file=/etc/kubernetes/audit/audit-policy.yaml
    - --audit-log-path=/var/log/kubernetes/audit/audit.log
    - --audit-log-maxbackup=10
    - --audit-log-maxsize=100
    volumeMounts:
    - mountPath: /etc/kubernetes/audit
      name: audit-conf
      readOnly: true
    - mountPath: /var/log/kubernetes
      name: audit-log
      readOnly: false

2. etcd 백업 및 복구 (Snapshot & Restore)

Control Plane의 핵심 데이터베이스인 etcd의 상태를 안전하게 백업하고 장애 발생 시 복구하는 필수 실습입니다.

① etcd 스냅샷 백업 생성:

ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/etcd-backup.db

② 스냅샷 복구 (Restore):

ETCDCTL_API=3 etcdctl snapshot restore /opt/etcd-backup.db \
  --data-dir=/var/lib/etcd-from-backup

3. SecurityContext 및 파일시스템 보호

컨테이너가 루트 권한으로 실행되는 것을 방지하고, 읽기 전용 루트 파일시스템을 적용해 악성 파일 변조를 차단합니다.

apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
  namespace: production
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 10001
    fsGroup: 10001
  containers:
  - name: app
    image: nginx:alpine
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
        - ALL
        add:
        - NET_BIND_SERVICE
    volumeMounts:
    - mountPath: /tmp
      name: tmp-dir
  volumes:
  - name: tmp-dir
    emptyDir: {}

4. Cilium L3/L4 및 FQDN 네트워크 정책

Cilium 환경에서 특정 파드 간의 트래픽을 허용하거나 거부하고, 외부 도메인(FQDN) 기반으로 송신을 제어합니다.

apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: secure-ingress-egress
  namespace: default
spec:
  endpointSelector:
    matchLabels:
      app: frontend
  ingress:
  - fromEndpoints:
    - matchLabels:
        app: proxy
    toPorts:
    - ports:
      - port: "8080"
        protocol: TCP
  egress:
  - toFQDNs:
    - matchName: "kplabs.in"
    toPorts:
    - ports:
      - port: "443"
        protocol: TCP

5. Trivy를 이용한 취약점 진단 및 SBOM 생성

컨테이너 이미지 내부의 OS 패키지 및 애플리케이션 라이브러리 취약점을 스캔하고 소프트웨어 구성 명세서를 추출합니다.

# 컨테이너 이미지 취약점 스캔 (HIGH, CRITICAL 등급 필터링)
trivy image --severity HIGH,CRITICAL nginx:alpine

# SBOM(Software Bill of Materials) 생성 (CycloneDX 형식)
trivy image --format cyclonedx --output sbom.json nginx:alpine

6. Falco 런타임 위협 탐지 규칙 설정

컨테이너 내부에서 발생할 수 있는 민감 파일(/etc/shadow) 읽기나 셸 실행 등의 비정상 행위를 실시간 탐지합니다.

사용자 정의 규칙 추가 (/etc/falco/falco_rules.local.yaml):

- rule: Detect Sensitive File Read in Container
  desc: Detect attempts to read sensitive system files inside a container
  condition: cont.id != host and open.read and (fd.name = /etc/shadow or fd.name = /etc/passwd)
  output: "Sensitive file read detected (user=%user.name command=%proc.cmdline file=%fd.name container_id=%container.id)"
  priority: CRITICAL

서비스 재시작 및 로그 확인:

sudo systemctl restart falco
journalctl -u falco -f

Kubernetes 순차 업그레이드

마이너 버전은 한 단계씩 순차 업그레이드해야 합니다 (예: 1.31 → 1.32 → 1.33). Control Plane 및 Node 업그레이드 명령어:

kubeadm upgrade plan
kubeadm upgrade apply v1.32.0
# kubelet은 별도 수동 업그레이드 필요
sudo apt-get update && sudo apt-get install -y kubelet=1.32.0-0 --allow-change-held-packages
sudo systemctl restart kubelet
