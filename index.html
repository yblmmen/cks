Chapter 1

Cluster Setup & Hardening

1. API Server 감사 로그 (Audit Log) 설정

클러스터 API 요청 추적을 위한 감사 정책 파일 및 API Server 매니페스트 설정입니다.

① 감사 정책 파일 작성 (/etc/kubernetes/audit/audit-policy.yaml):

apiVersion: audit.k8s.io/v1
kind: Policy
rules:
- level: RequestResponse
  resources:
  - group: ""
    resources: ["pods", "secrets", "configmaps"]

② API Server 매니페스트 수정 (/etc/kubernetes/manifests/kube-apiserver.yaml):

spec:
  containers:
  - name: kube-apiserver
    command:
    - kube-apiserver
    - --audit-policy-file=/etc/kubernetes/audit/audit-policy.yaml
    - --audit-log-path=/var/log/kubernetes/audit/audit.log
    - --audit-log-maxbackup=10
    - --audit-log-maxsize=100
    volumeMounts:
    - mountPath: /etc/kubernetes/audit
      name: audit-conf
      readOnly: true
    - mountPath: /var/log/kubernetes
      name: audit-log
      readOnly: false

2. etcd 스냅샷 백업 및 복구 (Snapshot & Restore)

etcdctl을 이용한 장애 대비 백업 및 복원 작업입니다.

# etcd 백업 생성
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/etcd-backup.db

# etcd 복구 (Restore)
ETCDCTL_API=3 etcdctl snapshot restore /opt/etcd-backup.db \
  --data-dir=/var/lib/etcd-from-backup

3. Kubernetes 클러스터 업그레이드 및 버전 스큐

마이너 버전 순차 업그레이드 및 kubeadm 활용 방법입니다.

kubeadm upgrade plan
kubeadm upgrade apply v1.32.0
sudo apt-get update && sudo apt-get install -y kubelet=1.32.0-0 --allow-change-held-packages
sudo systemctl restart kubelet

kubectl auth can-i get pods --as=system:serviceaccount:default:my-sa

# Role 및 RoleBinding 검사 후 불필요한 verbs(create, delete 등) 제거

2. ServiceAccount 토큰 자동 Mount 제어

파드가 불필요하게 API Server 토큰을 마운트하지 못하도록 설정합니다.

apiVersion: v1
kind: ServiceAccount
metadata:
  name: restricted-sa
  namespace: default
automountServiceAccountToken: false

Chapter 3

System Hardening

1. 커널 파라미터 및 Sysctl 제어

보안 강화를 위해 파드의 securityContext.sysctls를 통해 커널 설정을 제어합니다.

apiVersion: v1
kind: Pod
metadata:
  name: sysctl-pod
spec:
  securityContext:
    sysctls:
    - name: kernel.msgmax
      value: "65536"
  containers:
  - name: test
    image: busybox

2. AppArmor 및 Seccomp 프로파일 적용

시스템 콜(System Call)을 제한하여 컨테이너 탈출을 원천 방지합니다.

# Seccomp 프로파일 지정 예시 (Pod SecurityContext)
securityContext:
  seccompProfile:
    type: RuntimeDefault

3. Cilium L3/L4 및 FQDN 네트워크 정책

트래픽 통제를 위한 Cilium 네트워크 정책 구성입니다.

apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: secure-ingress-egress
  namespace: default
spec:
  endpointSelector:
    matchLabels:
      app: frontend
  egress:
  - toFQDNs:
    - matchName: "kplabs.in"
    toPorts:
    - ports:
      - port: "443"
        protocol: TCP

Chapter 4

Minimize Microservice Vulnerabilities

1. SecurityContext 및 파일시스템 보호

루트 권한 실행 금지 및 읽기 전용 루트 파일시스템 마운트 설정입니다.

apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 10001
    fsGroup: 10001
  containers:
  - name: app
    image: nginx:alpine
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop: ["ALL"]
        add: ["NET_BIND_SERVICE"]
    volumeMounts:
    - mountPath: /tmp
      name: tmp-dir
  volumes:
  - name: tmp-dir
    emptyDir: {}

2. Dockerfile 보안 및 제한 사용자 실행

FROM ubuntu:24.10
RUN useradd -u 10001 appuser
USER appuser
CMD ["./app"]

3. Trivy 이미지 진단 및 SBOM 생성

# 취약점 진단
trivy image --severity HIGH,CRITICAL nginx:alpine

# SBOM 생성 (CycloneDX 형식)
trivy image --format cyclonedx --output sbom.json nginx:alpine

1. Falco 런타임 위협 탐지 규칙 작성

컨테이너 내부 민감 파일 접근 및 비정상 행위 실시간 탐지입니다.

- rule: Detect Sensitive File Read in Container
  desc: Detect attempts to read sensitive system files inside a container
  condition: cont.id != host and open.read and (fd.name = /etc/shadow or fd.name = /etc/passwd)
  output: "Sensitive file read detected (user=%user.name command=%proc.cmdline file=%fd.name container_id=%container.id)"
  priority: CRITICAL
